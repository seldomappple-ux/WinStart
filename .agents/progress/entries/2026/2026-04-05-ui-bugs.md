验收"软件开关"功能时发现三个 UI bug：

1. **灰化图标位置漂移** — disabled 项切换后不保持原来的静态网格位置，图标会跑偏。根因：`set_items` 重建 balls 时位置依赖 `self.width()`，但在菜单关闭后 widget 尺寸可能尚未稳定，导致 `update_layout` 计算出错位置。修复：`set_items` 后强制调用 `update_layout`，确保静态位置以当前实际尺寸为准。

2. **图标名称/图片底部黑色背景框** — `ToggleMenuRow` 的 `icon_label` 和 `name_label` 继承了父级 QMenu 的背景色，显示为黑色矩形。修复：给这两个 label 显式设置 `background: transparent`。

3. **切换开关时卡顿** — `handle_toggle_item` 每次切换都调用 `icon_widget.set_items(self.items)`，该方法会重建全部 balls 并对每个 disabled 项执行逐像素灰化（`_make_grayscale_pixmap` 是 Python 层双重循环），56×56 图标约 3136 次像素操作，多个图标叠加导致明显卡顿。修复：在 `set_items` 时缓存灰化结果（按 path 缓存），或改为只更新单个 ball 的 icon 而不重建全部 balls。

补充校正:

- 后续复查发现，图标位置问题的更直接原因是 `paintEvent` 按固定 `icon_size` 居中绘制，但 `IconLoader.get_pixmap()` 返回的是保持比例缩放后的真实尺寸图标，不保证一定是 `56x56`。因此相同中心点下，不同图标会表现出视觉位移。最终修复应改为按 `pixmap.width()` / `pixmap.height()` 实际尺寸居中绘制。
- 开关卡顿的更直接原因是灰度缓存键不稳定，并且切换时仍会重复执行图标提取。最终修复应改为对 `IconLoader.get_pixmap()` 做稳定缓存，并让灰度缓存基于 `QPixmap.cacheKey()` 工作。
